# 测试与验收规范

验证证明用户需要的行为和风险边界；不以测试数量或覆盖率数字替代判断。当前已建立 pytest、Playwright、静态/类型与构建检查，实际命令见 [源码指南](../guides/source.md)，验证证据按批记录。

## 1. 按改动选择验证

| 改动类型 | 重点验证 |
| --- | --- |
| 纯文档 | UTF-8、相对链接、索引、状态/日期、示例与事实一致 |
| 纯视觉 | 实际页面、相关尺寸/主题、长中文、键盘与缩放 |
| 纯计算逻辑 | 正常、边界、错误与已知正确结果 |
| API/契约 | 入参、状态码、错误模型、权限、响应 schema、前端类型同步 |
| AI/MCP | 真实客户端发现/调用、界面等价结果、禁用、脱敏、伪造授权拦截 |
| 任务与进程 | 状态转换、重复提交、取消竞态、超时、退出、重启中断 |
| 数据/路径 | 迁移、回退限制、权限、穿越、并发、损坏/缺失数据 |
| 跨工具复用 | 真实调用链、契约兼容、依赖不可用、部分失败与清理 |
| 交付配置 | 干净环境构建、就绪、真实操作、持久化、停止和升级 |

不为低影响可逆改动添加与实现一一对应的测试，如断言 CSS 类名或文案常量。修复真实行为缺陷时，优先增加能复现原问题且能防回归的测试；修复前提应验证而非猜测。

## 2. 层次与候选工具

后端候选 pytest，前端候选 Vitest/Testing Library，端到端候选 Playwright；首次骨架实现后确定版本、目录、命令与环境要求。候选工具不表示已经安装或可运行。

- 单元测试围绕纯逻辑与服务决策，mock 外部边界，避免 mock 每个内部方法。
- 契约测试验证清单、操作 schema、HTTP 模型、错误和跨工具公开协议。
- 集成测试使用隔离数据库、临时目录、受控进程/网络替身，证明适配器与服务真实结合。
- 端到端覆盖少量关键用户流程：找到工具、输入、执行、查看结果、导出，以及关键失败恢复。
- 交付冒烟使用实际打包/容器产物，不用开发服务通过来替代成品验证。

## 3. 测试数据与环境

固定种子与时钟；时间测试包含时区边界。不得依赖用户绝对路径、已有工具安装、私人文件、真实账户、付费 API 或不稳定公网结果。

中文、空字符串、特殊字符、长路径、大输入和格式损坏按工具类型选取。测试输出进入临时目录并清理，不覆盖用户数据。需要额外依赖的集成测试明确标记，跳过记录说明原因。

避免通过真实等待模拟所有状态；以注入时钟和可控信号测试超时/取消。性能检查注明输入规模、机器条件、目标和容差，不把随机时间阈值变成普通单元测试。

## 4. 平台与运行形态

服务核心以 Windows 源码环境和 Linux Docker 为初始目标；桌面壳首先针对 Windows 验证。macOS/Linux 桌面只有实际验证后才声明支持。

首个可用工具至少验证源码浏览器与 Docker；引入桌面壳时补 Windows WebView。桌面专属能力单独检查，Docker 使用上传/下载替代；未测试形态在支持表中明确标注。

## 5. 必要质量检查

骨架阶段建立稳定入口，后续使用仓库真实存在的命令：格式/静态检查、类型检查、相关测试、构建、契约同步和文档检查。工具选择与命令写入源码指南，禁止在报告中伪造命令。

公共契约、共享模块、依赖或部署入口变化应检查实际消费方；纯工具私有改动以工具相关检查为主。发布时执行所有支持交付形态的验收；日常改动不重复无关完整矩阵。

检查通过后，无新改动、失败或未解风险时停止重复验证。因环境缺失而无法执行的检查单列，不把“跳过”“静态分析正常”写成运行通过。

## 6. 证据与问题关闭

工作记录注明命令/方法、工作目录、环境、结果和必要输出摘要。界面问题可附相关截图，敏感信息先脱敏；不提交大体积、可再生成或无价值的完整日志。

关闭问题需要原复现条件下验证修复，以及受影响关键路径回归。验证不足时问题继续保留，注明待验证项；真正完成后从当前问题清单删除，摘要进入日志。
