# 安全、权限与数据规范

工具可能处理任意文件、调用本地程序或联网。保护数据与明确访问范围是平台责任，不能分散成每个工具各自实现的隐含规则。

MCP 操作与界面共用权限和业务执行层；行为提示 annotations 不是授权。当前仅开放 read-only，副作用操作默认拒绝，新增能力需按 [MCP 规范](mcp.md) 建立可信用户授权。桌面随机凭据只由原生请求事件附加，不能放在页面/URL；不得因已校验 Cookie 而省略该检查。

## 1. 默认信任模型

默认单用户、受信任内置工具、服务绑定本机。模块化不提供代码沙箱；第三方不可信插件、远程多用户、组织权限管理均不属于初始承诺，加入前需要重新设计隔离与身份边界。

工具声明所需能力，平台按运行模式和配置判定是否可用；界面显示需求，后端仍执行鉴权、路径和资源校验。

## 2. 本机服务与桌面桥

- 桌面服务绑定 127.0.0.1/受控回环地址，使用随机可用端口与本次启动的高熵会话凭据；回环地址本身不是身份校验。
- 本机浏览器模式也需要本机会话建立机制，防止其他网页驱动本机 API。不能用固定、写入前端包的共享密钥保护所有安装实例。
- 会话初始化通过受控引导流程建立，不把长期密钥写进 URL、日志或普通持久化。桌面可信桥仅传递必要的短期凭据和原生能力。
- 校验 Host 与允许来源，防止 DNS rebinding；有 Origin 的状态变更请求校验来源，无 Origin 的请求也必须携带有效会话。Cookie 鉴权另实施 CSRF 防护，CORS 不能代替鉴权。
- 开发跨域仅允许具体开发来源；生产优先同源。凭据场景禁止任意来源放行。
- WebView 导航限制为可信本地页面；外链交给系统浏览器，并禁止外部页面访问原生桥。危险桥接方法不得暴露任意命令执行或任意路径访问。

本地服务也需考虑 CSRF，参考 [pywebview 官方安全说明](https://pywebview.flowrl.com/guide/security.html)。具体引导与会话机制在实现时写入契约和验证方案。

## 3. 文件与产物

- 文件服务统一控制允许根目录、读写范围、大小、格式、保留期与所有权；用户在 UI 选择路径不代表任意后续访问均被授权。
- 处理路径规范化、目录穿越、符号链接/Windows junction、UNC 路径和平台大小写差异；最终目标必须仍位于允许根目录。敏感操作同时考虑检查与使用间的替换风险。
- 文件名作为展示元信息，不直接用作未经清理的路径。上传产生受控 ID，下载通过鉴权获取，不提供任意路径读取接口。
- 覆盖采用安全写入/原子替换，在目标目录内写临时文件；需要恢复的操作先备份。删除/移动确认实际目标与范围，默认不操作源码或用户无关目录。
- 解压限制条目数、总体积、压缩比，防止路径穿越和资源耗尽；格式处理不完全信任扩展名/MIME。
- Docker 只访问显式卷和应用数据目录；浏览器上传和宿主卷权限是不同来源，分别说明。
- 默认任务产物按保留策略清理，运行中引用受保护；导出到用户目录的文件不随缓存清理删除。

## 4. 外部程序、网络与资源

执行程序使用明确可执行文件与参数数组，默认不经过 shell。输入不能拼接成命令；用户输入不能直接成为可执行路径。限制工作目录、环境变量、输出体积、超时和子进程树生命周期。

进程适配器说明依赖安装、来源、版本、许可、退出码和失败恢复；不能默默下载安装执行代码。宿主工具在 Docker 内需要独立安装和验证，不能假设可直接调用 Windows 软件。

联网工具声明目的、数据去向、凭据与费用。URL 输入按功能建立协议、域名/地址和重定向约束，避免绕过保护访问元数据地址或内网服务；确需内网的工具明确授权范围。HTTP 请求设置超时、响应大小、并发和有限重试。

为上传、队列、任务并发、执行时间、临时空间和日志设置上限。高风险本地库或工具进程使用适当隔离；普通异常捕获不是资源隔离。

## 5. 配置、秘密与隐私

普通配置与密钥分离。环境变量/本机系统凭据库/受控挂载秘密按运行模式选择；密钥不提交 Git、不打包进前端、不复制到清单、工作日志或截图。

默认离线可用，不自动遥测、上传诊断或同步用户文件。必须联网的工具在使用前说明传输内容。日志仅记必要元信息，敏感输入与内容脱敏；诊断导出让用户知道包含什么。

数据清理入口说明范围：缓存、任务记录、产物、设置和用户导出分别控制。删除敏感数据时需说明备份和存储介质中的残留限制，不承诺不可实现的物理擦除。

## 6. Docker 与远程访问

容器内服务可绑定 0.0.0.0，但默认宿主发布端口绑定 127.0.0.1；对局域网/公网开放属于不同部署模式，需要身份认证、HTTPS/可信反代、会话隔离和相应验收，不能只改绑定地址就宣称安全支持。

默认非 root、最小权限，不挂 Docker socket，不使用 privileged。只挂实际需要目录，必要只读挂载；运行数据与只读应用分开。第三方依赖与基础镜像固定可追溯版本，更新时验证兼容性与已知风险。
