# UI 与交互规范

纯布局、样式、文案任务读取 AGENTS.md 和本文件即可开始；接入数据或原生能力时再读对应前端规范。本规范定义初始设计基线，首个界面实现后以统一设计令牌和共享组件固化。

## 1. 产品信息结构

工具箱以“找到工具、完成操作、取得结果”为主线。初期导航包含工具目录、任务、设置和帮助；收藏、最近使用等按实际需求渐进增加。

- 工具目录提供搜索、分类和明确的可用状态；搜索至少匹配名称、说明和标签。
- 单工具页面保留统一导航，标题下说明用途、输入要求和必要限制，不迫使用户先读技术文档。
- 工具可定制专用工作区，但复用平台的上传、任务、错误、结果与设置模式。
- 公共入口不塞入只属于某一个工具的选项；工具专用设置留在工具页。
- 无可用工具、搜索无结果和工具被禁用是不同状态，分别给出有用提示。

## 2. 基础布局与视觉

| 项目 | 初始约定 |
| --- | --- |
| 布局 | 桌面侧栏 + 标题/操作区 + 工具工作区；窄屏侧栏折叠 |
| 间距 | 4、8、12、16、24、32 px 为主；少量例外需有布局理由 |
| 字号 | 正文以 14–16 px 为主，辅助文字通常不低于 12 px |
| 字体 | 系统中文无衬线字体回退；代码/路径使用等宽字体 |
| 圆角 | 普通控件 6–8 px，容器 8–12 px，统一令牌 |
| 输入/按钮 | 常规高度约 36–40 px；触控界面使用更大点击区域 |
| 配色 | 中性背景、一种主色、统一成功/警告/失败/信息语义色 |
| 主题 | 新组件使用语义令牌；主题能力实现后统一提供明暗方案 |
| 动效 | 短、可中断；尊重 reduced-motion，不用于阻塞工作 |

颜色、字号、阴影、边框、层级等进入集中令牌，不散落大量硬编码值。主题色由首个正式 UI 任务确定并文档化，不在每个工具中另选一套视觉系统。

约 1280×800 是常用桌面验证尺寸，900×600 检查紧凑窗口，约 390 px 宽检查浏览器窄屏退化。断点由内容能否正常使用决定，不仅按设备名。大工作区可扩展，不强制所有工具使用固定宽度卡片。

## 3. 标准工具工作区

推荐顺序为输入 → 参数 → 主操作 → 状态 → 结果。简单工具在一个连续页面完成；复杂工具可以使用左右分栏或分步流程，窄屏仍有清晰顺序。

- 一块工作区通常只有一个明确主操作；取消、重置、导出等有次要层级。
- 默认值安全且可解释；高级参数折叠，不把普通任务变成配置表格。
- 输入校验贴近字段显示，保留用户输入；不只在顶部弹出笼统失败消息。
- 上传区说明格式、大小、批量支持和数据去向；桌面文件选择与浏览器上传使用一致的用户语言。
- 结果提供实际需要的预览、复制、下载或传递到其他工具入口；传递需明确目标及数据内容。
- 重置、删除、覆盖等动作说明作用范围，有不可逆后果时使用具体确认文案。

## 可点击内容的约定

有意义的内容尽量提供可操作入口：卡片整体进入工具，标签执行筛选，状态打开原因说明，帮助/隐私提示展开说明，版本展示关于信息。使用原生链接、按钮和 details；嵌套操作有独立焦点，不能把按钮嵌入链接。普通正文和纯装饰不伪装成按钮，不添加没有结果的点击、空跳转或虚假功能。弹窗支持关闭、Escape 和焦点恢复。

## 4. 状态与反馈

每个工具至少设计初始、校验失败、执行中、成功、执行失败、能力不可用状态；有任务取消时再设计取消中、已取消和中断状态。

执行中展示真实阶段；总量未知使用不定进度，禁止假百分比。操作提交后防止重复点击，耗时任务允许离开页面并从任务入口继续查看。不能把整个应用锁在全屏加载框里。

成功提示说明产物位置或下一步；有部分成功时说明成功/失败数量和失败项。失败提示给出原因、可执行的恢复动作和诊断编号，避免只显示“发生错误”。重要失败与结果持久可见，不能只依赖短暂 toast。

按钮禁用时需能知道原因。网络断开、服务重启、任务中断分别处理，保留可恢复草稿；服务重连不能自动重新提交有副作用的操作。

## 5. 文案与帮助

用户可见文案默认简体中文，按钮使用具体动词，如“转换”“导出”“重试”。路径和标识符保持原值，不翻译代码字段；时间、文件大小与数量使用一致格式。

不把 Python、容器内部目录、协议名称等实现细节放进普通操作步骤；只有用户需要配置环境或排查时才显示。外部联网、费用、数据上传、文件覆盖等会影响用户选择的信息应在动作前说明。

每个工具有可发现的帮助入口，帮助页面或工具内说明使用当前功能文档/指南的受控内容。说明要版本一致、短而准确，不展示整份开发规范。

## 6. 可访问性

- 使用语义化表单、按钮与标题；字段有可关联标签，图标按钮有可理解名称。
- 键盘可完成主要流程；焦点可见，弹窗管理焦点、关闭后回到触发位置；禁止键盘陷阱。
- 状态不能只用颜色区分；文本、图标与颜色共同说明。正文对比度以至少 4.5:1 为设计目标，大字号和非文本控件按相关要求验证。
- 支持 200% 缩放而不丢失主要操作；列表、分栏与长路径有合理换行/滚动。
- 进度和错误以合适方式向辅助技术播报，避免每次微小进度变化不断打断。
- 快捷键有说明、避免抢占普通输入；所有快捷操作保留按钮入口。

## 7. UI 验收与留证

检查常用与紧凑尺寸、长中文、空结果、大输入、错误、执行中、能力缺失、键盘和缩放。共享样式变化在真实页面验证；设计主题后也检查相应主题。

有可用 UI 环境时实际打开页面检查并保存有价值的截图；截图置于 docs/assets/{feature_id}/，文件名包含日期和语义，索引注明环境。没有运行环境时写明仅做静态检查，不声称视觉验收通过。

不为像素值、CSS 类名或静态文案编写与实现一一对应的单元测试。组件行为、可访问性和交互逻辑需要实质验证。
