# 后端开发规范

## 1. 职责与风格

API 层处理鉴权、入参、调用和响应；服务层表达用例；纯业务逻辑可脱离 HTTP 测试；适配层负责数据库、文件、网络和进程。小功能按职责自然组织，不强制套用完整领域驱动框架。

公开函数、跨模块接口及复杂结构写类型。Python 使用 snake_case、类使用 PascalCase。通过项目统一的格式化、静态检查与类型检查配置维护风格，不在任务中单独更改全库格式。

禁止模块导入时启动服务、访问数据库、下载资源或执行任务。依赖通过启动装配注入；资源创建和释放归应用生命周期管理。

## 2. API 约定

- 公共前缀使用 /api/v1；工具接口归 /api/v1/tools/{tool_id}/，任务归 /api/v1/jobs/，文件归 /api/v1/artifacts/。
- 接口定义包含字段语义、必填/默认、范围、示例、错误和能力条件。Pydantic 模型与 OpenAPI 为 HTTP 类型来源；前端生成类型后仍需处理不可信响应。
- 请求和响应字段统一 snake_case；时间采用含时区 ISO 8601，持久化统一 UTC，界面按用户时区显示。日期工作记录使用 Asia/Shanghai。
- 标识符不使用显示名称；列表默认分页，排序条件和上限明确；文件内容走文件接口，不把大二进制塞入 JSON。
- 普通成功响应直接返回明确模型，不机械套多层 data；集合返回 items、total、next_cursor 中实际需要的字段。
- 采用真实 HTTP 状态码：参数错误 422、未认证 401、无权限 403、资源不存在 404、状态冲突 409、限流 429、依赖暂不可用 503。失败不得伪装成 200。
- 可预期错误统一为 error.code、error.message、error.details、request_id；details 仅包含可安全呈现的字段级信息。框架默认异常须转换成一致模型，不能暴露堆栈、密钥或完整内部路径。
- 机器依赖稳定错误码，界面呈现可理解的中文信息，文档列出恢复方式。未知异常由边界处理器记录完整诊断信息并返回安全提示。
- GET 不产生业务写入；破坏性动作有明确接口和范围。请求重试不默认意味着业务可重复执行。

## 3. 工具契约与执行入口

所有工具通过注册器装配。计算操作使用统一操作契约，参考 [工具接入规范](tool-development.md)；确有特殊需求的上传、预览或流式端点可独立路由，但最终复用同一服务逻辑、错误和权限机制。

平台需要提供目录及能力查询，响应区分声明能力、运行环境可用能力和禁用原因。前端不能依赖只存在于静态菜单中的工具清单。

## 4. 同步操作与任务

- 时间短、有上限、无需进度或取消的操作可以同步。文件批量处理、外部命令、耗时不确定或需要进度的操作进入任务服务。
- 异步操作先持久化任务记录，再返回 202 和 job_id。任务负载记录输入引用与执行所需配置快照；密钥仅保留安全引用。
- 统一状态：queued、running、cancel_requested、succeeded、failed、cancelled、interrupted。终态不回到执行中；重试创建新任务并记录来源。
- running 收到取消先进入 cancel_requested；完成与取消竞态通过原子状态更新裁决。已完成的任务不能被标成 cancelled；不支持中断的操作应提前声明。
- 进度支持“未知总量”，不得生成虚假百分比。更新包含阶段、已处理量、可选总量和可选安全提示。
- 有限并发、排队上限、超时和资源限制集中配置。I/O 工作使用适合的线程/异步适配；CPU 密集工作和需强制终止的命令使用受控进程，不能阻塞事件循环。
- 首期单调度实例。重启后未完成的 running/cancel_requested 记录标为 interrupted；只有声明可安全重放的 queued 任务才恢复，否则也标记 interrupted。不得自动重复执行有副作用的操作。
- 幂等键按会话/操作/有效期隔离，并结合请求摘要校验；用于防止重复提交，不代表外部系统具备恰好一次语义。
- 重试必须受错误类型、次数和副作用约束；删除、覆盖、付款等操作不能盲目自动重试。
- 平台清理任务产物、临时文件和历史数据的保留策略可配置，运行中的输入不能被回收。

HTTP 响应后的简单辅助动作可使用框架后台任务；需要持久状态、重启恢复、取消或隔离的工作不能仅依赖它。[FastAPI 官方后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)也区分轻量后台动作与重计算场景。

## 5. 存储与配置

- 数据库存取经过仓储/明确查询边界，工具不得直接访问其他工具的私有表。事务范围小而明确，不在长事务中等待用户或外部网络。
- SQLite 用于首期单实例本地存储；配置忙等待与必要索引，按实测评估日志模式。不要把数据库文件放在多人共享网络文件系统中使用。
- 有数据库变更时建立版本化迁移；失败停止相关启动步骤，先备份再迁移，并说明是否可回退。引入 SQLAlchemy/Alembic 等库以实际需求为准。
- 配置集中、类型化校验，优先级统一为命令行显式值 > 环境变量 > 用户配置 > 默认值。密钥不写普通配置文件；来源见安全规范。
- 工作目录可变化；路径服务区分配置、数据、缓存、日志和临时目录。

## 6. 日志与可观测性

每次请求带 request_id，任务带 job_id，工具带 tool_id/operation_id。采用结构化日志，记录时间、级别、事件和耗时；输入内容、令牌、文件正文默认不记日志。

提供存活与就绪检查。存活只判断进程服务状态；就绪判断核心初始化、数据迁移及必要资源。可选工具不可用在目录中报告，不应把整个应用永久标为未就绪。

日志轮转、最大体积和保留期有默认值与配置说明；用户应能获取脱敏诊断信息。
