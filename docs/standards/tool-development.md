# 工具接入与能力复用规范

## 1. 范围与原则

“工具”是用户可独立选择的功能单元；“操作”是工具提供的执行能力；“共享能力”是多个工具需要的业务或基础能力。工具不限类型，既可以有专用页面，也可以是前端纯计算、Python 模块或外部程序适配。

首期只支持受信任、随应用构建的工具。新增工具通常需要更新注册项、安装声明依赖、重新构建/启动；模块化不等于无需重启或能安全安装任意第三方代码。

## 2. 工具清单

每个工具有唯一清单，位于 apps/server/src/mtools/tools/{tool_package}/manifest.json。tool_package 使用 tool_ 前缀，再将 tool_id 中的横线映射为下划线，如 text-normalizer 对应 tool_text_normalizer，以避免 Python 关键字冲突；前端路径和公开 ID 仍使用 tool_id。前端纯计算工具也必须有声明式目录项，但不因此添加虚假的 Python 业务实现。

| 字段 | 要求 |
| --- | --- |
| manifest_version | 清单结构版本，初始为 1 |
| tool_id | 稳定小写 kebab-case，匹配 ^[a-z][a-z0-9]*(-[a-z0-9]+)*$；Python 包名映射规则集中实现 |
| version | 工具版本，使用语义化版本 |
| name、description | 中文显示名称与用途，不当作标识符 |
| category、tags | 可检索分类与标签 |
| execution_target | frontend、backend 或 external；表示主要执行位置 |
| supported_modes | source-web、desktop、docker-web 中明确支持的形态 |
| required_capabilities | filesystem、network、clipboard 等实际需要的权限/环境能力 |
| dependencies | 依赖工具/共享能力的公开 ID、兼容范围及是否可选 |
| operations | 操作 ID、契约版本、中文标题/用途、输入/输出 schema 引用、effects、ai_callable=true、超时、取消/幂等能力 |
| ui | 工具路由或通用页面类型；构建入口由受控前端注册表映射 |
| docs | 对应当前功能文档与使用指南的仓库路径 |

实现清单 schema 后，字段名、必填规则、枚举及版本迁移以 contracts 中的定义为唯一来源，本表同步维护。执行入口不能从清单任意路径动态导入；代码入口由可信注册器显式关联 tool_id。

清单是声明，运行目录是实际状态。运行目录至少区分 available、disabled、unavailable、incompatible，附安全可呈现的原因及实际可用操作。平台 API 返回前端需要的清单投影，不暴露内部路径、密钥或可执行文件细节。

## 3. 操作契约

- 操作由 tool_id + operation_id + contract_version 唯一定位，命名清晰且稳定。
- 每个操作定义可验证的输入/输出，包含上限、默认值、单位、编码、错误、文件引用和副作用。
- 后端模型生成 JSON Schema/OpenAPI；前端纯计算操作也建立正式 schema，避免前后端各写不一致的字段。
- 输入通过校验后才执行；输出在公开边界保证符合契约。不可把实现对象、数据库连接或裸 Python 异常交给其他工具。
- 文件使用 artifact_id 及名称、类型、大小等安全元信息；artifact_id 必须经过访问检查，不等同于任意路径访问授权。
- 结果包含机器可用数据与必要展示信息，不强迫下游解析中文提示文字或 UI HTML。
- 超时、最大输入量、执行位置、取消支持、可否重试/重放都须声明。不可取消的操作不能显示已取消。

统一后端执行入口形状为 POST /api/v1/tools/{tool_id}/operations/{operation_id}/execute。当前已实现 JSON 格式化、文本差异、JSON/JSONL 与编码/摘要同步操作，输入携带契约版本和参数，返回明确结果模型；各工具显式注册强类型路由。任务模式尚未实现，未来实现后返回 202、job_id、status_url，不能提前作为现有接口使用。当前以 OpenAPI 和 [平台契约子集](../features/platform-shell/overview.md) 为事实来源。

每个公开操作必须可供 AI 调用，遵守 [MCP 规范](mcp.md)。当前 OperationHandler 绑定输入/输出模型和处理器，ToolRuntime 共用于 HTTP 与 MCP；清单 schema 名与模型不一致时拒绝装配。纯前端操作也需提供可信 AI 执行适配器，不能仅注册页面或伪造后端持久任务。需要持久历史或后台运行时才迁移/委托到后端。特殊上传、预览接口见后端规范。

## 4. 上下文与权限

工具接收最小的执行上下文：配置快照、安全文件服务、日志、任务进度/取消令牌、需要的公开能力调用接口。执行上下文不得变成可访问全应用内部对象的万能容器。

工具不自己硬编码路径、建立全局会话或绕过权限。声明 filesystem 只说明需求，具体路径与动作仍要由平台授权。外部命令、网络、危险文件操作参考 [安全与数据规范](security-data.md)。

工具的私有数据以 tool_id 命名空间隔离。公共文件/任务有平台所有权与访问机制，禁止通过猜测 ID 获取其他会话数据。

## 5. 生命周期与失败边界

注册过程为读取并校验清单 → 校验 ID 和契约 → 解析依赖 → 探测环境能力 → 装配受信任入口 → 暴露目录状态。

- 重复 ID、未知版本、循环依赖必须明确报错；不可默默覆盖注册项。
- 核心平台配置/存储错误阻止启动；可选工具的缺失依赖或普通初始化异常使该工具 unavailable，不阻止其他工具。
- 依赖工具不可用时，下游工具按必需/可选依赖降级并显示原因；禁用工具前处理在途任务，禁止静默丢任务。
- 启动探测不执行真实用户任务，不自动下载可执行代码或模型；下载属于明确可见的资源管理流程。
- 关闭时释放资源和子进程；native 崩溃、内存耗尽等不能依赖普通异常处理隔离，应选择进程适配器和资源约束。

## 6. 复用与跨工具组合

首先判断复用对象：两处使用同一计算逻辑，优先提取 shared；一个工具明确使用另一个工具的完整公开操作，则通过平台能力调用器组合。

共享能力有职责、输入/输出、异常与测试；不从某工具抽出大量不相关代码，不建立无所不包的基础类。跨工具依赖在清单中声明，平台启动时检查有向无环图和契约版本兼容性。

跨工具调用复用服务层或公开操作适配器，不通过本机 HTTP 自调用模拟内部复用。传播任务关联 ID、取消信号、资源预算和安全上下文；后端不能直接调用仅前端可执行的能力，除非该工作流明确在客户端编排。

简单串行组合使用明确的编排服务即可。每一步约定数据转换、失败/部分成功、临时产物清理和重试边界；有副作用步骤需要补偿策略或人工恢复说明，禁止宣称天然原子事务。按需支持把上一工具结果传给下一工具，不预建通用可视化工作流引擎。

## 7. 新工具接入步骤

1. 明确用途、输入输出、支持形态、副作用、验收案例，建立稳定 tool_id 与 feature_id。
2. 查询已有工具/共享模块和文档，决定复用点与执行位置，避免重复实现。
3. 定义清单与操作契约，声明环境能力、依赖和资源上限。
4. 实现独立业务模块及必要适配，添加可信后端/前端注册项。
5. 实现页面和标准状态，检查不可用环境及数据传递行为。
6. 使用真实 MCP 客户端完成发现、调用与界面等价结果，检查停用及权限；验证错误、边界、取消/超时及必要组合，按支持形态验证交付。
7. 建立 docs/features/{feature_id}/overview.md 与 usage.md，更新索引、变更日志和当日工作记录。

没有后端、特殊 UI 或持久化需求时，不创建对应空模块。所有步骤以实际需要展开。

## 8. 最小验收清单

- 每项公开操作可由 MCP 发现和实际调用；副作用权限不依赖模型自述授权。
- 能在目录中找到，ID 唯一，禁用/缺依赖不会导致其他工具普通功能失效。
- 输入输出契约明确，有正常、异常和边界案例；声明的环境能力真实可用。
- 不越过模块与权限边界，无硬编码本机路径，无私有实现跨工具导入。
- 清单声明的运行形态已验证或明确尚未验证，不将桌面特性冒充 Docker 特性。
- 当前功能说明、使用方法、限制和维护记录齐全；不存在已修复但仍列为未解决的问题。
