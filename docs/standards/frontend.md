# 前端开发规范

视觉与交互细则见 [UI 规范](ui.md)。本文件只约束前端结构、数据与环境边界。

## 1. 模块与注册

- app 负责路由、外层布局、依赖装配和全局错误边界；platform 提供工具目录、任务、能力查询等客户端；tools/{tool_id} 维护独立工具页面。
- 工具通过明确的本地前端注册表映射 tool_id、路由和懒加载入口。导航信息来自校验后的清单/API，前端注册项只负责构建期页面映射，不另建一套工具业务元数据。
- 前端只有加载受信任的构建产物，不执行服务端返回的 JavaScript、任意 import 路径或远端脚本。
- 共享组件分为基础控件、平台组件和真正复用的业务组件。工具私有组件留在工具目录；不因“将来可能复用”提前抽象。
- 工具页面不得 import 其他工具内部组件或状态；通过共享组件、文件引用或公开能力组合。

## 2. 类型、API 与错误

TypeScript 开启严格模式。避免 any 和不解释的类型断言；不可信 JSON、持久化设置和桥接响应要校验。

HTTP 契约由后端模型/OpenAPI 生成到 generated/，工具清单类型由统一契约生成。生成文件带来源说明，不手改；变更生成源与产物同步提交。前端专用视图模型允许单独存在，不复制服务端业务校验作为唯一保护。

API 客户端集中处理基地址、会话、request_id、超时、取消、错误模型和重试条件。各页面不自行拼接生产域名、令牌或底层请求逻辑。开发代理与生产同源策略有清晰边界。

提交按钮需防重复提交；有副作用的请求不可自动重试。请求取消与后端任务取消是两件事：关闭页面的网络请求不代表任务已停止。

## 3. 状态归属

| 状态 | 归属 |
| --- | --- |
| 页面筛选、打开的面板、表单草稿 | 工具页面或局部组件 |
| 可分享的筛选、当前工具/任务 | 路由参数，敏感值不得入 URL |
| 服务端工具目录、任务结果 | 统一服务端状态缓存，失效规则明确 |
| 主题、语言、布局偏好 | 统一设置入口，可版本化持久化 |
| 原生能力与权限 | 运行环境能力服务 |

不把所有表单和结果塞入全局 store。服务器响应保持单一缓存来源；派生值实时计算，避免冗余同步。只有确有跨页面需求时增加全局状态或新的状态库。

## 4. 运行环境与能力

- 业务组件依赖统一 runtime 接口，而不是直接访问 window.pywebview 或本机文件系统。
- 桌面适配只提供必要原生能力；计算、任务和业务校验仍通过共享业务 API。当前不暴露通用 JS/Python 桥，桌面实例必须有原生请求凭据，不能在普通浏览器中降级打开；浏览器开发和 Docker 通过显式服务模式使用同一前端。
- 浏览器选择文件后上传得到 artifact_id；不能向服务器提交客户端绝对路径来模拟上传。
- 按能力响应展示可用操作。不可用按钮显示原因/替代路径，不能静默点击无效或仅靠隐藏按钮实现权限控制。
- 生产资源优先本地打包，核心界面不依赖 CDN 字体、脚本或图标；确需联网的工具明确提示。
- 使用浏览器兼容路由及静态资源策略，直接刷新工具深层路由也能打开；桌面与 Docker 的基路径行为需验证。

## 5. 任务、文件与性能

任务状态以服务端为准，初期允许带退避的轮询；确有需要时再使用 SSE/WebSocket。切换工具后仍可在任务入口查询状态；重连时先获取快照再接收后续更新。

大文本、大表格和大结果使用分页、虚拟化或受控预览，不把整个文件同步渲染到 DOM。工具页面懒加载，重计算移出 UI 主线程。上传、预览和导出分别设大小上限与清理规则。

每个工具有局部错误边界；一个页面异常不阻断导航与其他工具。异常页面提供返回、重试和诊断编号；禁止捕获异常后只在控制台打印而让用户无反馈。

## 6. 完成检查

前端行为变更检查类型、相关交互、失败状态、能力缺失和必要的深层路由。纯样式调整按 UI 规范做视觉验证；新增数据流、权限或任务流程需要相应契约/集成验证。

共享组件变化检查至少一个真实消费页面；不能只用孤立组件截图证明整页兼容。
